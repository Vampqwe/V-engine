# ⚙️ V-ENGINE

## Операционная система для веб-приложений

> **Не CMS. Не фреймворк. Не продукт.**  
> Это инфраструктура, на которой вы строите свой продукт.

---

## 💡 ГЛАВНАЯ ИДЕЯ

Представьте **операционную систему** (Windows, Linux, macOS). Она не знает, что такое "текстовый редактор" или "браузер". Она предоставляет:
- Файловую систему
- Управление памятью
- Безопасность
- Сетевой стек

А вы пишете приложения, которые используют эту инфраструктуру.

**V-Engine — это такая ОС для веб-приложений.**

Ядро не знает про "блоги", "магазины" или "форумы". Оно предоставляет:
- Безопасность (CSRF, XSS, SQL-защита)
- Хранение данных (БД, файлы, кэш)
- Рендеринг шаблонов
- Сессии и куки
- Самодиагностику

А вы пишете бизнес-логику, используя эту инфраструктуру.

---

## 🎯 КЛЮЧЕВЫЕ ПРИНЦИПЫ

### 1. Две дороги

Существует **два пути** выполнения кода:

```
ПУТЬ ЯДРА (инфраструктура)          ПУТЬ ПОЛЬЗОВАТЕЛЯ (бизнес-логика)
─────────────────────────          ─────────────────────────────────
• Безопасность                     • Контроллеры
• Сессии                           • Модели
• Кэш                              • Сервисы
• Шаблоны                          • Работа с БД
• Логи                             • Рендеринг

        ╔═══════════════════════════════════════╗
        ║  ТОЧКИ ВЗАИМОДЕЙСТВИЯ                 ║
        ║  • DI-контейнер                       ║
        ║  • Событийная шина                    ║
        ║  • Контракты (интерфейсы)             ║
        ╚═══════════════════════════════════════╝
```

Эти пути **не пересекаются** напрямую. Пересечение происходит только через **Точки Взаимодействия**.

### 2. Контракты вместо реализаций

Пользователь **никогда** не видит внутреннюю реализацию ядра. Он работает только с **интерфейсами**:

```php
// ❌ НЕПРАВИЛЬНО (прямой доступ к реализации)
$db = new \Core\Database\PdoDriver();
$db->query('SELECT * FROM users');

// ✅ ПРАВИЛЬНО (работа через контракт)
$db = $container->get(DatabaseInterface::class);
$db->find('users', ['id' => 1]);
```

### 3. Автоматическая безопасность

Безопасность работает **молча** и **автоматически**:
- CSRF-защита применяется ко всем POST-запросам
- XSS-экранирование работает через функцию `e()`
- SQL-инъекции невозможны (prepared statements)
- Валидация входных данных — автоматическая

Пользователь не может "забыть" защитить форму. Ядро делает это за него.

### 4. Пустая БД — не ошибка

Если пользователь не настроил БД в `.env`:
- Ядро **не падает**
- Работает режим "статика"
- Doctor выдаёт Warning: "БД не настроена"
- Статические сайты, лендинги работают полноценно

### 5. Админка — изолированный бог

Админка живёт **отдельно** от основного сайта:
- Отдельный роутер (`/admin/*`)
- Отдельная авторизация (SuperAdmin)
- Видит всё, но никто не трогает её
- Работает как SPA (статика + API)

### 6. Самодиагностика (Doctor)

Doctor — это **честность** перед пользователем. Он говорит:
- Работает ли БД?
- Валиден ли APP_KEY?
- Актуален ли кэш?
- Есть ли проблемы с правами файлов?

Два контура валидации:
- **Lex** (статический анализ) — проверяет код на соответствие Конституции
- **Doctor** (живая среда) — проверяет работоспособность системы

### 7. PHP-First подход

Движок использует **только встроенные возможности PHP**:
- PDO для БД
- cURL для HTTP
- GD для изображений
- OpenSSL/Sodium для криптографии
- DateTime для дат

**Нулевые сторонние зависимости** в production. Только PHPUnit для тестов.

### 8. Шаблоны — нативный PHP

Никаких компиляторов (Twig, Blade, Latte). Шаблоны — это обычные `.phtml` файлы с PHP:

```php
<h1><?= e($title) ?></h1>
<?php foreach ($items as $item): ?>
    <li><?= e($item['name']) ?></li>
<?php endforeach; ?>
```

Функция `e()` гарантирует безопасность. Lex следит, чтобы вы не забыли её использовать.

## 🔌 КАК ЭТО РАБОТАЕТ

### Жизненный цикл запроса

```
1. Клиент → public/index.php
2. Аварийный люк (500 Hardcode)
3. Загрузка .env
4. Bootstrap ядра (Kernel::boot)
5. Регистрация перехватчиков ошибок
6. Маршрутизатор (развилка):
   ├─ /admin/*     → Админка (изолированный бог)
   ├─ /system/health → Doctor (самодиагностика)
   └─ /*           → Путь пользователя
7. Middleware Pipeline (автоматическая безопасность):
   ├─ Rate Limit
   ├─ CSRF verify
   ├─ XSS sanitize
   ├─ Input validation
   └─ Session decrypt
8. Контроллер пользователя:
   ├─ $db->find() (через контракт)
   ├─ $view->render() (через контракт)
   └─ Возврат ответа
9. Обратный путь ядра:
   ├─ Компиляция шаблона
   ├─ XSS-экранирование вывода
   ├─ Set-Cookie
   └─ HTTP-ответ клиенту
```

## 🎯 ДЛЯ КОГО ЭТО

**V-Engine для вас, если:**
- ✅ Вы хотите полный контроль над кодом
- ✅ Вы не хотите зависеть от сторонних пакетов
- ✅ Вы цените безопасность и предсказуемость
- ✅ Вы готовы писать инфраструктуру сами (или использовать готовую)
- ✅ Вы понимаете PHP и ООП

**V-Engine НЕ для вас, если:**
- ❌ Вы хотите "всё и сразу" из коробки
- ❌ Вы не хотите разбираться в архитектуре
- ❌ Вы привыкли к Laravel/Symfony и не хотите менять подход
- ❌ Вам нужны готовые CMS-решения
